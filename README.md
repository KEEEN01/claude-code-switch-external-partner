# Claude Code で 一般社団法人Switch 案件を回すための導入ガイド（外部パートナー向け）

このガイドは、**すでにClaude Code を使っている外部パートナー** が、
**Switch案件を回すために必要な3ツール（Aqua Voice / Google Cloud / GitHub）を導入** し、
**Switch を1クライアントとして既存ワークフローに組み込む** ための実務手順書です。

---

## 想定読者と前提

- **既に Claude Code を日常的に使っている**（これだけが必須前提）
- 複数クライアントを並行して回している
- Switch はその中の1社（あるいは数社中の1社）

これから本ガイドで導入してもらうもの：
1. **Aqua Voice**（音声入力）— Switch案件は長文業務が多いので必須レベル
2. **Google Cloud（Google Workspace MCP）** — SwitchはGoogle系で運営されているので必須
3. **GitHub**（gh CLI＋リポジトリ運用）— 稼働証跡・タスク管理・Claude Code連携のため

---

## 所要時間
**約2〜3時間**で全PART完了。導入ツール3つで約60〜90分、Switch固有設定で60〜90分。
初日に全部やる必要はなく、案件キックオフまでに段階的に整えればOK。

## 2-1. Aqua Voice を導入する（15分）

### なぜ必要か
Switch案件は **自治体提案書・月次報告書・利用者対応メール** など、長文業務が多発します。
音声で口頭入力できるかどうかで、生産性が2〜3倍変わります。

### 2-1-A. プラン選択

| プラン | 価格 | 使える量 |
|--------|------|---------|
| Starter（無料） | $0 | 月1,000単語まで／カスタム辞書5個 |
| **Pro（推奨）** | $8/月（年額） | 無制限／カスタム辞書800個 |
| Team | $12/月 | Pro＋チーム管理 |

外部パートナーで毎日Switch業務を扱うなら **Pro必須**。

### 2-1-B. インストール

#### Macの場合
1. [aquavoice.com](https://aquavoice.com/) で「Download for Mac」→ `.dmg` ダウンロード
2. `.dmg` を開いて Applications にドラッグ
3. アプリ起動
4. **マイクアクセス許可** → 「許可」
5. **アクセシビリティ権限** → `システム設定 → プライバシーとセキュリティ → アクセシビリティ` でAqua Voiceをオン

#### Windowsの場合
1. [aquavoice.com](https://aquavoice.com/) で「Download for Windows」→ `.exe` ダウンロード
2. `.exe` を実行（SmartScreen警告が出たら「詳細情報」→「実行」）
3. アプリ起動
4. マイク許可：`設定 → プライバシーとセキュリティ → マイク` で許可

### 2-1-C. 初回設定

1. アカウント作成（Google or メール）
2. プラン選択（Starterで試行 → Proへ移行が無難）
3. **キーボードショートカット** を確認（デフォルト：Fnキー長押し）

### 2-1-D. 【重要】Switch用語をカスタム辞書に登録

固有名詞は登録しないと誤認識されるので、最初に必ず：

| カテゴリ | 登録すべき単語 |
|---------|--------------|
| 法人名 | 一般社団法人Switch、Switch（スイッチ）、Switch Terrace |
| 関連法人 | 株式会社Shift（混同注意） |
| 自治体名 | 田村市（たむらし）、福島県（ふくしまけん）など担当自治体 |
| 事業領域 | 移住定住、自治体委託、廃校サテライト、教育委託 |
| Switch側担当者名 | キックオフ後に追加（フルネーム＋読み） |

### 2-1-E. 音声入力の安全ルール

**機密情報は音声入力しない**（Aqua Voiceはクラウド送信されるため）：

| 音声入力OK | 音声入力NG（手入力） |
|----------|-------------------|
| 一般的な提案文・企画文 | 自治体担当者の氏名 |
| 自治体名（公開情報） | 利用者・受講者の個人情報 |
| 抽象化された数字（「数百万円台」） | 具体的な契約金額・口座番号 |

> 個人情報を含む案件では、**OS標準のオフライン音声入力**（Mac標準 / Windows `Win+H`）に切り替える運用もアリです。

### 2-1-F. 動作確認

メモ帳など適当な場所にカーソルを置いて、Fnキー長押しで何か話す → 文字化されればOK。

## 2-2. Google Cloud（Google Workspace MCP）を導入する（30〜45分）

### なぜ必要か
Switch は **Gmail / Calendar / Drive / Docs / Sheets** で運営されています。
Claude Code から直接これらを読み書きできるようにすると、メール下書き・予定登録・Drive内資料の検索が口頭指示でできるようになります。

### 2-2-A. OAuth プロジェクトの方針を決める

| 方針 | メリット | デメリット | おすすめ |
|------|---------|-----------|---------|
| 既存のOAuthプロジェクトを流用 | 設定が1回で済む | 全クライアントが同じトークンで動く | 個人パートナーで案件が少ない場合 |
| **Switch専用OAuthプロジェクトを作成** | 案件終了時にトークン削除で完全分離 | 初期設定が2回必要 | **複数案件を厳格分離したい外部パートナー（推奨）** |

以下は **Switch専用に分ける場合の手順**。既存流用ならスキップしてMCPの接続だけ確認してください。

### 2-2-B. 【ブラウザ】Google Cloud プロジェクトを作る

1. [console.cloud.google.com](https://console.cloud.google.com/) を開く
2. 上部のプロジェクト選択 → 「新しいプロジェクト」
3. 名前：`claude-mcp-switch`（外部パートナーは識別しやすい名前を）
4. 「作成」 → 数秒で完了
5. 作成したプロジェクトを **選択中** にする

### 2-2-C. 【ブラウザ】5つのAPIを有効化

左メニュー → 「APIとサービス」 → 「ライブラリ」で以下を1つずつ検索＆「有効にする」：
- Gmail API
- Google Calendar API
- Google Drive API
- Google Docs API
- Google Sheets API

### 2-2-D. 【ブラウザ】OAuth同意画面を設定

左メニュー → 「APIとサービス」 → 「OAuth同意画面」
1. User Type：`外部` → 作成
2. アプリ名：`claude-mcp-switch`、サポートメール／デベロッパー連絡先は自分のGmail
3. スコープ：そのまま「保存して次へ」
4. テストユーザー：自分のGmailを追加
5. 「ダッシュボードに戻る」

### 2-2-E. 【ブラウザ】OAuthクライアントIDを作る

左メニュー → 「APIとサービス」 → 「認証情報」
1. 「+ 認証情報を作成」 → 「OAuth クライアント ID」
2. アプリケーションの種類：**デスクトップアプリ**
3. 名前：`claude-mcp-switch-client`
4. 作成 → 「JSON をダウンロード」
5. ダウンロードファイルを `credentials.json` にリネーム

### 2-2-F. 【Claude Codeに頼む】credentials.jsonを安全に配置

```
ダウンロードフォルダにある client_secret_で始まるJSONファイルを、
Switch専用パス ~/.config/google-mcp-switch/credentials.json にリネーム＆移動してください。

手順：
1. ~/.config/google-mcp-switch/ フォルダがなければ作成
2. ダウンロードフォルダから該当ファイルを移動
3. ファイル名を credentials.json に変更
4. 完了後、配置先のファイル一覧を見せて

このファイルは絶対にGitHubに上げない（後で.gitignore登録します）。
```

### 2-2-G. 【Claude Codeに頼む】.mcp.json に Switch用MCPサーバーを追加

```
私の作業ルートの .mcp.json に、Switch専用のgoogle-workspace MCPサーバーを追加してください。

追加するエントリ：
"google-workspace-switch": {
  "command": "uvx",
  "args": ["workspace-mcp"],
  "env": {
    "GOOGLE_OAUTH_CLIENT_SECRETS_FILE": "/Users/[私のユーザー名]/.config/google-mcp-switch/credentials.json"
  }
}

既存のmcpServersブロックがあれば、その中に追記してください。
[私のユーザー名] は whoami で確認して埋めてください。

完了後、ファイルの中身を見せて確認させてください。
```

### 2-2-H. Claude Code を再起動 → 認証

1. Claude Codeを一度終了して再起動
2. 入力欄に：

```
google-workspace-switch のGoogle認証を開始してください。
mcp__google-workspace-switch__start_google_auth を実行してブラウザでログイン画面を開いてください。
```

3. ブラウザで自分のGoogleアカウントを選択
4. 「このアプリは確認されていません」→「詳細」→「(アプリ名) に移動」→「許可」
5. 「認証完了」が出ればOK

### 2-2-I. 動作確認

```
google-workspace-switch 経由で、今日のGoogleカレンダーの予定を取得してください。
```

→ 予定が返ってくれば成功。

# PART 3: Switchの3事業と受託しやすい業務領域（10分）

## 3-1. 法人プロフィール

- **法人名**: 一般社団法人Switch（**株式会社Shiftとは別法人**。命名が似ているので混同注意）
- **拠点**: 福島県（田村市など）
- **Webサイト（事業の1つ）**: [switch-terrace.com](https://switch-terrace.com/)

## 3-2. Switchの3事業

| # | 事業 | 内容 | 外部スタッフが受託しやすい業務 |
|---|------|------|----------------------------|
| 1 | **自治体委託業務** | 田村市移住定住促進事業など | 提案書作成支援／月次報告書作成／移住イベント企画／補助金リサーチ |
| 2 | **Switch Terrace** | 廃校サテライトオフィス運営 | 利用者集客のSNS運用／Web更新／イベント企画／撮影・編集／設備マニュアル整備 |
| 3 | **教育事業** | 自治体委託＋自社プログラム開発 | カリキュラム設計／教材制作／受講者管理／講師リサーチ／自治体営業資料作成 |

## 3-3. 外部スタッフが受託「しない」領域

| 領域 | 理由 |
|------|------|
| 自治体との **契約締結** や **契約金額交渉** | 法人代表・管理者の判断領域 |
| 自治体担当者・利用者・受講者の **個人情報の直接取扱い** | 個人情報保護・法人責任 |
| Switch の **採用・人事** | 法人内部判断 |
| メディア取材・対外発信の **最終承認** | ブランド責任 |
| 競合案件（同種の自治体委託・他社教育事業の同類サービス）の **同時並行受託** | 利益相反のリスク → 受託前にSwitchに開示要 |

これらの仕事を依頼されたら、いったん「**Switch代表/管理者に確認します**」と保留してください。

# PART 4: 自分の環境にSwitch用フォルダを切る（10分）

## 4-1. 推奨フォルダ構造

既存のClaude Code作業環境の中に、**クライアント別** にディレクトリを切る方式を推奨。

```
あなたの作業ルート/
├── CLAUDE.md            既存（あなた全体のメタマニュアル）
├── .claude/commands/    既存スキル
├── clients/
│   ├── switch/          ← Switch案件はここに集約
│   │   ├── CLAUDE.md    Switch専用コンテキスト（後で作る）
│   │   ├── strategy/    Switch側戦略のメモ・引用
│   │   ├── jichitai/    自治体委託案件
│   │   ├── terrace/     Switch Terrace案件
│   │   ├── education/   教育事業案件
│   │   ├── meetings/    打ち合わせメモ・議事録
│   │   ├── deliverables/ 納品物
│   │   └── billing/     稼働時間・請求書（機密）
│   ├── client-a/        他社案件
│   └── client-b/        他社案件
└── output/              AI出力
```

> **ポイント**：自分の他案件と **物理的に隔離** すること。Claude Codeに作業フォルダを `clients/switch/` に切り替えて作業すれば、他クライアントの情報が混入する事故を防げます。

## 4-2. 【Claude Codeに頼む】フォルダ一括作成

Claude Codeの入力欄に：

```
私の作業ルート（CLAUDE.mdがあるフォルダ）の下に、
新規クライアント「一般社団法人Switch」用のフォルダ構造を作ってください。

構造：
clients/switch/strategy/
clients/switch/jichitai/
clients/switch/terrace/
clients/switch/education/
clients/switch/meetings/
clients/switch/deliverables/
```

# PART 8: 機密情報・スコープ・競合配慮の作法（10分）

## 8-1. 機密データの3層構造

| 層 | 例 | 取扱いルール |
|----|-----|------------|
| **厳重** | 自治体契約書／個人情報／法人経理 | GitHub絶対NG／音声入力NG／Driveは共有元のみ／案件終了時に削除 |
| **通常機密** | 提案書草稿／戦略メモ／打ち合わせ議事録 | GitHubはプライベートリポジトリのみ／.gitignoreで管理 |
| **公開可** | Web公開済の情報（switch-terrace.com 等）／公表済リリース | 自由に引用可 |

## 8-2. AIに渡してはいけない情報

外部パートナーとして特に注意：
- **個人氏名と組織名のセット**（例：「田村市の◯◯さん」）→ 匿名化（「田村市A担当」）
- **契約金額の具体額** → 「□□万円台」など抽象化
- **未公開のSwitch内部議論** → そもそも外部に出ない範囲を確認

> 機密度が判断できないものは、**作業前に Switch窓口に確認** が原則。

## 8-3. 競合・利益相反への配慮

複数クライアントを持つ外部パートナー特有のリスク。

| シナリオ | 対処 |
|---------|------|
| 同じ自治体の別事業の案件が別社経由で来た | Switchに **事前開示** して可否を確認 |
| 競合する廃校サテライト施設の案件オファー | 受託前に Switch側 と相談 |
| 同種の教育プログラムを他社向けに開発中 | 守秘範囲を明確に区切る／必要なら Chinese Wall |

## 8-4. 案件終了時のデータ削除

案件終了 or 契約終了後、原則として **3ヶ月以内** に以下を実施：
- Switch から共有された Drive ファイルのアクセス権返却
- ローカルの `clients/switch/` フォルダのアーカイブ／削除
- GitHubリポジトリの Collaborator 解除依頼
- Switch専用OAuth（google-workspace-switch）のトークン削除
- 完了報告書 を Switch に送付

# PART 12: トラブル・エスカレーション

## 12-1. よくあるトラブルとClaude Codeへの相談例

| 症状 | Claude Codeへの相談プロンプト |
|------|-----------------------------|
| Switch CLAUDE.mdが無視される | 「clients/switch/CLAUDE.md の内容を読んで、現在のセッションで適用されているか確認して」 |
| 競合配慮の判断に迷う | 「以下の状況、Switchに開示すべきかどうかフレームで整理して：[状況]」 |
| 機密情報を誤って共有しそう | 「これから送るこのファイル、Switchに渡すと問題ある情報含まれてない？確認して：[ファイル名]」 |
| 急ぎなのに動かない | スクリーンショットを貼って「これ何が原因？」 |
| 過去案件のパターン使いまわしたい | 「clients/switch/deliverables/ から、[類似条件]の過去案件を探して、流用ポイント教えて」 |
| google-workspace-switch が認識されない | 「.mcp.json の中身を見せて、Switchエントリが正しく書かれているか確認して」 |
| Aqua Voiceの日本語精度が悪い | カスタム辞書に固有名詞を追加（PART 2-1-D 参照） |

## 12-2. Switchへの即連絡が必要なケース

- 自治体・利用者・受講者から直接連絡が来た
- 想定外のスコープ拡大依頼が来た
- 納期遅延の見込み
- 機密情報の取り扱いに少しでも不安がある
- 同種・競合案件のオファーが他社から来た

→ 即座にSwitch側窓口に **電話 or チャットで** 連絡。メールだと埋もれます。

## 12-3. Claude Codeで品質を担保する3つの習慣

1. **作業前**：「これからやること、私のスコープ内？確認して」
2. **作業中**：1時間ごとに「ここまでの作業、品質OK？問題点ある？」と自己レビュー指示
3. **納品前**：「この成果物、Switchに出して恥ずかしくない？素直に課題指摘して」
