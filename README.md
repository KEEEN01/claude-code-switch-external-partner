# Claude Code で 一般社団法人Switch 案件を回すための導入ガイド（外部パートナー向け）

このガイドは、**すでに自分の環境で Claude Code を活用している外部パートナー** が、
**一般社団法人Switch を1クライアントとして** 既存ワークフローに組み込むための実務手順書です。

---

## 想定読者

- 既に Claude Code を日常的に使っている
- 自分専用の `.claude/commands/` やCLAUDE.mdを持っている、もしくは作ったことがある
- 複数クライアントを並行して回している
- Switchはその中の1社（あるいは数社中の1社）

未経験者向けの基礎セットアップ（OS基本環境／Aqua Voice／Anthropic契約／Google Cloud／GitHub等）は本ガイドの **対象外** です。未済の方は別ガイドを先にどうぞ：
- Mac: [claude-code-setup-guide-mac](https://github.com/KEEEN01/claude-code-setup-guide-mac)
- Windows: [claude-code-setup-guide-windows](https://github.com/KEEEN01/claude-code-setup-guide-windows)

# PART 2: Switchの3事業と受託しやすい業務領域（10分）

## 2-1. 法人プロフィール

- **法人名**: 一般社団法人Switch（**株式会社Shiftとは別法人**。命名が似ているので混同注意）
- **拠点**: 福島県（田村市など）
- **Webサイト（事業の1つ）**: [switch-terrace.com](https://switch-terrace.com/)

## 2-2. Switchの3事業

| # | 事業 | 内容 | 外部スタッフが受託しやすい業務 |
|---|------|------|----------------------------|
| 1 | **自治体委託業務** | 田村市移住定住促進事業など | 提案書作成支援／月次報告書作成／移住イベント企画／補助金リサーチ |
| 2 | **Switch Terrace** | 廃校サテライトオフィス運営 | 利用者集客のSNS運用／Web更新／イベント企画／撮影・編集／設備マニュアル整備 |
| 3 | **教育事業** | 自治体委託＋自社プログラム開発 | カリキュラム設計／教材制作／受講者管理／講師リサーチ／自治体営業資料作成 |

## 2-3. 外部スタッフが受託「しない」領域

| 領域 | 理由 |
|------|------|
| 自治体との **契約締結** や **契約金額交渉** | 法人代表・管理者の判断領域 |
| 自治体担当者・利用者・受講者の **個人情報の直接取扱い** | 個人情報保護・法人責任 |
| Switch の **採用・人事** | 法人内部判断 |
| メディア取材・対外発信の **最終承認** | ブランド責任 |
| 競合案件（同種の自治体委託・他社教育事業の同類サービス）の **同時並行受託** | 利益相反のリスク → 受託前にSwitchに開示要 |

これらの仕事を依頼されたら、いったん「**Switch代表/管理者に確認します**」と保留してください。

# PART 3: 自分の環境にSwitch用フォルダを切る（10分）

## 3-1. 推奨フォルダ構造

既存のClaude Code作業環境の中に、**クライアント別** にディレクトリを切る方式を推奨。

```
あなたの作業ルート/
├── CLAUDE.md            既存（あなた全体のメタマニュアル）
├── .claude/commands/    既存スキル
├── clients/
│   ├── switch/          ← Switch案件はここに集約
│   │   ├── CLAUDE.md    Switch専用コンテキスト（後で作る）
│   │   ├── strategy/    Switch側戦略のメモ・引用
│   │   ├── jichitai/    自治体委託案件
│   │   ├── terrace/     Switch Terrace案件
│   │   ├── education/   教育事業案件
│   │   ├── meetings/    打ち合わせメモ・議事録
│   │   ├── deliverables/ 納品物
│   │   └── billing/     稼働時間・請求書（機密）
│   ├── client-a/        他社案件
│   └── client-b/        他社案件
└── output/              AI出力
```

> **ポイント**：自分の他案件と **物理的に隔離** すること。Claude Codeに作業フォルダを `clients/switch/` に切り替えて作業すれば、他クライアントの情報が混入する事故を防げます。

## 3-2. 【Claude Codeに頼む】フォルダ一括作成

Claude Codeの入力欄に：

```
私の作業ルート（CLAUDE.mdがあるフォルダ）の下に、
新規クライアント「一般社団法人Switch」用のフォルダ構造を作ってください。

構造：
clients/switch/strategy/
clients/switch/jichitai/
clients/switch/terrace/
clients/switch/education/
clients/switch/meetings/
clients/switch/deliverables/
clients/switch/billing/

既存のclients/フォルダがなければ新規作成してOK。
完了後、ls -R clients/switch/ で確認させてください。
```

## 3-3. 【Claude Codeに頼む】.gitignore に機密フォルダ追加

```
私の作業ルートの .gitignore に、以下を追加してください：

# Switch案件 機密フォルダ
clients/switch/billing/
clients/switch/jichitai/*/contracts/
clients/switch/jichitai/*/personal_data/
clients/switch/terrace/bookings/
clients/switch/education/students/

追加したら、その部分だけ私に見せてください。
```

# PART 5: Switch案件用 CLAUDE.md を作る（15分）

これが **本ガイドの一番のキモ**。Switch案件のフォルダに **専用のミニCLAUDE.md** を置くことで、

## 5-1. 【Claude Codeに頼む】Switch用 CLAUDE.md を生成

```

含めてほしいセクション：

1. クライアント概要
   - 法人名：一般社団法人Switch（株式会社Shiftとは別法人）
   - 拠点：福島県
   - 代表：（私にヒアリングで埋めて）
   - Webサイト（事業の1つ）：switch-terrace.com

2. Switchの3事業
   - 自治体委託業務（田村市移住定住など）
   - Switch Terrace（廃校サテライトオフィス）
   - 教育事業（自治体委託＋自社プログラム）

3. 私の受託スコープ
   - 受託している業務領域：（私にヒアリングで埋めて）
   - 受託していない領域：契約交渉／個人情報直接取扱／人事／メディア承認

4. 連絡先・コミュニケーション
   - Switch側窓口：（ヒアリング）

# PART 7: 機密情報・スコープ・競合配慮の作法（10分）

## 7-1. 機密データの3層構造

| 層 | 例 | 取扱いルール |
|----|-----|------------|
| **🔴 厳重** | 自治体契約書／個人情報／法人経理 | GitHub絶対NG／音声入力NG／Driveは共有元のみ／案件終了時に削除 |
| **🟡 通常機密** | 提案書草稿／戦略メモ／打ち合わせ議事録 | GitHubはプライベートリポジトリのみ／.gitignoreで管理 |
| **🟢 公開可** | Web公開済の情報（switch-terrace.com 等）／公表済リリース | 自由に引用可 |

## 7-2. AIに渡してはいけない情報

外部パートナーとして特に注意：
- **個人氏名と組織名のセット**（例：「田村市の◯◯さん」）→ 匿名化（「田村市A担当」）
- **契約金額の具体額** → 「□□万円台」など抽象化
- **未公開のSwitch内部議論** → そもそも外部に出ない範囲を確認

> 機密度が判断できないものは、**作業前に Switch窓口に確認** が原則。

## 7-3. 競合・利益相反への配慮

複数クライアントを持つ外部パートナー特有のリスク。

| シナリオ | 対処 |
|---------|------|
| 同じ自治体の別事業の案件が別社経由で来た | Switchに **事前開示** して可否を確認 |
| 競合する廃校サテライト施設の案件オファー | 受託前に Switch側 と相談 |
| 同種の教育プログラムを他社向けに開発中 | 守秘範囲を明確に区切る／必要なら Chinese Wall |

## 7-4. 案件終了時のデータ削除

案件終了 or 契約終了後、原則として **3ヶ月以内** に以下を実施：
- Switch から共有された Drive ファイルのアクセス権返却
- ローカルの `clients/switch/` フォルダのアーカイブ／削除
- GitHubリポジトリの Collaborator 解除依頼
- 完了報告書 を Switch に送付

# PART 8: コミュニケーション・報告のプロトコル（5分）

## 8-1. 推奨される報告頻度

| 報告種別 | 頻度 | 内容 |
|---------|------|------|

| **緊急連絡** | 都度 | スコープ外要望・スケジュール影響・問題発覚時 |

## 8-2. 【Claude Codeに頼む】週次サマリーを自動生成

```
今週の Switch 案件の作業を、週次サマリーにまとめてください。

データソース：
- clients/switch/ フォルダ内のファイル更新履歴

- 今週コミットしたファイル

サマリーの構成：
1. 今週やったこと（成果物名・進捗％）
2. 来週やること（優先順位順）
3. Switchに確認したい事項
4. 今週の稼働時間（概算）

clients/switch/meetings/weekly_summary_[今週の月曜の日付].md として保存して、
コピペでメール送れる形式で見せてください。
```

## 8-3. エスカレーション・トリガー

以下が起きたら **即・人間でSwitchに連絡**（Claude Code任せにしない）：
- スコープ外の依頼が来た

- 納期に間に合わない見込み
- 自治体・利用者・受講者からのクレーム伝達
- 自分の体調不良等で長期離脱の可能性

## 12-1. OS基本環境の再確認

Switch案件で **詰まりやすい基本環境の点検** リストです。
Claude Codeに以下を貼って一括チェック：

```
私のOS環境を、Switch案件を回すための観点で総点検してください。

確認項目：
1. OS：Mac / Windows どちらか、バージョン
2. ターミナル（Mac: Terminal.app / Windows: PowerShell）が起動可能
3. Git のバージョン（gh --version、git --version）
4. Node.js / npm のバージョン（node --version、npm --version）
5. Claude Code CLI のバージョン（claude --version）— 入れていれば
6. Google Drive for Desktop が同期している
7. ディスク残量（Switch案件のデータ受領に十分か）
8. 最終OSアップデート日

未整備・古い項目があれば、優先度（高／中／低）付きで「先にこれを直すべき」と提案してください。
```

### よくある「動いてるつもりで動いてない」ケース

| 症状 | 原因 | 対処 |
|------|------|------|
| `gh` が `command not found` | gh CLIのPATHが切れている | ターミナル再起動 or Macなら `brew reinstall gh` |
| Google Driveに最新ファイルが見えない | Drive同期が遅延／停止 | メニューバーのDrive アイコン → 同期状態確認 |
| Claude Codeでファイルが読めない | 作業フォルダが別案件のまま | 「作業フォルダを clients/switch/ に切り替えて」 |
| `node` のバージョンが古い | 1年以上更新していない | Macなら `brew upgrade node`、Windowsなら `winget upgrade OpenJS.NodeJS` |

### Switch案件を始める前の30秒チェック（毎日）

Claude Codeに：

```
今日のSwitch案件を始めます。
- 作業フォルダ：clients/switch/ になっているか
- Google Drive 同期は最新か
- 私の preferences.md / clients/switch/CLAUDE.md は読み込まれているか

### 12-3-1. OAuth プロジェクトを分けるか統合するか

| 方針 | メリット | デメリット | 推奨度 |
|------|---------|-----------|--------|
| **既存OAuthプロジェクトを流用** | 設定が1回で済む | 全クライアントが同じトークンで動く | ◯（個人パートナー） |
| **Switch専用OAuthプロジェクトを別途作成** | 案件終了時にトークン削除で完全分離 | 初期設定が2回必要 | ◎（複数案件を厳格分離したい場合） |

Switch専用に分ける場合の手順（要約）：
1. Google Cloud Console で「新しいプロジェクト」（例：`claude-mcp-switch`）
2. 5つのAPI有効化（Gmail / Calendar / Drive / Docs / Sheets）
3. OAuth クライアントID（デスクトップアプリ）作成 → credentials.json ダウンロード
4. `~/.config/google-mcp-switch/credentials.json` 等、Switch専用パスに配置
5. `.mcp.json` で `google-workspace-switch` という別MCPサーバーとして登録
6. Claude Codeに「Switchのgoogle認証を開始して」と依頼

| 自分のIssueには `partner:[自分の名前/ID]` ラベル（Switchが用意してくれていれば） | 担当者特定のため |

### 12-4-4. 自分側のGitHubでSwitch案件を管理する場合

外部パートナーが **自分側のリポジトリ** にSwitch案件をまとめる場合の構成例：

```
自分のメインリポジトリ（プライベート）
├── .gitignore（clients/*/billing/, clients/switch/jichitai/*/contracts/ などを除外）
└── clients/
    └── switch/
        ├── （PART 3で作ったフォルダ構造）
        └── ...
```

**重要**: 自分側で管理する場合も、Switch側機密ファイルは絶対に **公開リポジトリには上げない**。
プライベートリポジトリのみで、かつ.gitignore必須。

### 12-4-5. コミットメッセージのプライバシー

意外と見落としがちな点：

```
コミットメッセージに以下を含めないこと：
- Switch側担当者の実名
- 具体的な契約金額
- 自治体担当者の連絡先

OK例：
"自治体A向け提案書 v2: 構成見直し"
"Terrace 月次レポート 2026-04 ドラフト"

NG例：
"田村市の◯◯さんからの修正依頼を反映"
"500万円見積もりに更新"
```

Claude Codeにコミットを頼むときは：

```
コミットメッセージを作って push してください。
- 個人名・具体金額は伏せて
- 案件名・対象月・変更概要を簡潔に
- 機密度の高い変更は「内部メモ更新」程度にぼかす
```
